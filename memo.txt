includerは

---
1. Which Stream ends go to __OS_spawn__?

From the child’s side, standard input is the read end and standard output/error are the write ends. So inputStream should be an input Stream (read end) and outputStream/errorStream should be output Streams (write ends).
A wrong direction or a closed Stream goes to onError.

2. A way to pass the interpreter’s own standard I/O

Passing null for a Stream argument means the child inherits the interpreter’s own stdin/stdout/stderr. Before spawning, the interpreter flushes its own buffered output so the order doesn’t get mixed up.

3. Who closes the parent’s copies of the Streams?

__OS_spawn__ doesn’t close anything; the program closes the Streams it no longer needs with __OS_close__. The tests also demonstrate this. Closing them automatically on spawn is another option.

4. Locating the executable

If the first element of commandMSeq contains /, use it as a path; otherwise search the PATH in envDict. That is the same as execvpe, i.e. the environment is exactly envDict.
The working directory is the interpreter’s current directory.
An empty MSeq, a non-String element, or a non-String key/value in envDict goes to onError.
Exec failures (not found, no permission) also go to onError.

5. Exit status of a process killed by a signal

Return the signal number as a negative value (e.g. -9), as Python does. The shell-style 128 + signal number is the other option.
After a process has exited, __OS_poll__ keeps returning the same exit code.

6. OS processes still running when the interpreter exits

Leave them running, neither waiting for nor killing them. Waiting for them, or killing them, are the other options.

7. How to wait for exit

__OS_poll__ doesn’t block, so waiting means looping on it while yielding to other VProcs (busy waiting).

8. __OS_get_envDict__

It returns a new Dict copied from the interpreter’s environment variables. Changing that Dict doesn’t change the interpreter’s own environment.

9. Displaying an OSProc value

Like VProc, it’s shown with a sequential number, (__OSProc__ "N"), not the PID, because the PID changes on every run.

10. Commands used in tests

To get the same results on macOS and Linux, the tests only use /bin/sh, /bin/echo, /bin/cat and /usr/bin/env. Every output and every exit code is read only after __OS_poll__ has confirmed the process exited, which keeps the logs deterministic.
