# ConSh

ConSh は ConMa 言語で動作するシェルである。仕様と設計は [PLAN-ja.md](PLAN-ja.md) にある。

## 構成

```
consh/
├── PLAN-ja.md           仕様と設計
├── AST.md               consh_parse が出力する構文木の形式（英語）
├── bin/
│   ├── consh            ConSh を起動する（consh_parse --pos で構文木を作り、ConMa 版に渡す）
│   └── consh_parse      Python の参照実装：構文解析と語の展開の結果をテキストで出す
├── include/
│   ├── consh_main.se    main：ConSh の入口
│   ├── consh_ast.se     consh_parse の構文木の読み込みと書き戻し
│   ├── consh_parser.se  構文解析（当面は consh_parse を使うので空）
│   ├── consh_util.se    LList、LazyList、Dict の補助関数
│   ├── consh_expand.se  語の展開
│   └── consh_eval.se    文の実行
└── test/
    ├── run_all.sh       すべての test.sh を実行する
    ├── common.sh        各 test.sh が共通に使うパスと関数
    ├── parse1/          文法のテスト：caseN.sh を consh_parse に渡し、caseN.log と比べる
    ├── parse2/          構文木の位置のテスト：consh_parse --pos に渡す
    ├── expand1/         語の展開のテスト：consh_parse --expand に渡す。caseN.args の各行が引数になる
    └── stepN/           ConMa 版のテスト：test.sh, caseN.log。step1 は構文木の読み込み、step2 は単純な文、step3 は関数
```

* ConSh のために ConMa に足すプリミティブやライブラリは、`consh/` ではなく、リポジトリのルートの `docs/`、`include/`、`test/` に置く。
* `include/` のファイルには、ルートの `include/` のファイルと名前がぶつからないよう、`consh_` を付ける。
* 大きくなったら、`consh_lexer.se`、`consh_expand.se`、`consh_builtin.se` などに分ける。

## 実行

```
bin/consh [--dump] スクリプト [引数 ...]
```

ConMa 版は構文解析をせず、Python の `consh_parse --pos` が作った構文木のファイルを読む（形式は [AST.md](AST.md)）。
`--dump` を付けると、実行せず、ConMa 版が読んだ構文木を S 式に書き戻して出す。
ConMa のモジュールは `/tmp/consh.module.se` に作り、`.se` のソースが変わったときだけ作り直す。

### できること（段階 3）

* 変数定義、`export`、前置の変数定義、語の展開（コマンド置換と glob を除く）
* 外部コマンドの起動と `$?`。スクリプトは最後の文の `$?` で終わる
* ファイルへのリダイレクト（`<`、`>`、`>>`、`2>`、`2>&1`、`1>&2`）
* 関数の定義と呼び出し、変数リスト `(a b . rest)`、`return`、レキシカルスコープ、前置の変数定義の層
* 組み込みコマンド `echo`、`cd`、`builtin`、`command`

パイプ、`&`、コマンド置換、変数リストへのリダイレクト、`$$` は、まだ実行できない（エラーになる）。

標準出力は、要素（行）の並びとして扱う。

* トップレベルの標準出力は、要素を1行ずつ書く。
* 外部コマンドの標準出力は、パイプで受け取って行ごとの要素にする。そのため、最後の行に改行がなければ改行が付き、`\r\n` は改行になる（PLAN-ja.md の 1.3）。ただし、外部コマンド自身の `> ファイル` は、バイト列をそのまま書く。
* 関数の標準出力をファイルに向けると（`f > ファイル`）、関数の中の外部コマンドの出力も行ごとの要素にして、1行ずつ書く。
* 標準エラー出力は、要素にせず、そのまま書く。ただし `2>&1` で標準出力と同じ行き先にしたときは、標準出力と同じ要素の並びに入る。

仕様にない部分は、次のようにした。

* 変数定義、`export`、関数定義の文の後、`$?` は 0 になる（Bash と同じ）。本体が空の関数の戻り値も 0。
* 環境変数は、起動時の環境変数から始める。局所変数には取り込まないが、局所変数がなければ参照できる。
* 仕様で「エラーとする」もの（未定義の局所変数の `export`、リダイレクト元の重複、リダイレクト先が1語にならない、関数の中の `$1`、`$@`、`$#`、0 から 255 でない `return`、まだないもの）は、メッセージを出して終了ステータス 1 で終わる。
* コマンドを起動できない場合は `$?` を 127、ファイルを開けない場合や `cd` できない場合は 1 にして続ける。
* 語がすべて消えた単純文は、リダイレクトだけを行い、`$?` を 0 にする。
* `echo` はオプションを取らず、引数を空白で区切って連結した1つの要素を出す。
* `cd` は、それを実行した VProc のカレントディレクトリを変える（ConMa の Step 23）。今はシェル全体が1つの VProc で動くので、シェルのカレントディレクトリが変わる。

構文木と展開の結果を見るには、Python の参照実装を使う。構文木の形式は [AST.md](AST.md)、展開の結果の形式は `bin/consh_parse` の先頭に書いてある。`--pos` を付けると、構文木に行と桁が入る。

```
bin/consh_parse [--pos] スクリプト
bin/consh_parse --expand スクリプト [引数 ...]
```
