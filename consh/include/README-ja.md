# consh/include：ConMa 版 ConSh の高速版

ConMa 版の ConSh には、2 つの版がある。

* **参照版**（`consh/reference`）：仕様の参照実装。読みやすさを優先して書く。
* **高速版**（このフォルダ）：参照版のうち、速くするために書き直したファイルだけを置く。

高速版は、このフォルダ、`consh/reference` の順に include ディレクトリを指定して作る（`--include consh/include --include consh/reference`）。
include は、include ディレクトリを指定の順に探すので（docs/INCLUDER.md）、このフォルダにあるファイルは、どのファイルから include されても、`consh/reference` の同じ名前のファイルの代わりになる。
ここにないファイルは `consh/reference` のものを使う。最初のファイル（`consh_main.se`）も、ここになければ `consh/reference` のものを使う。

`bin/consh` は、`CONSH_IMPL=conma` で高速版、`CONSH_IMPL=reference` で参照版を動かす（既定は Rust 版）。

* 機能を足したり変えたりしたときは、参照版を直し、ここにあるファイルにも同じ変更をして、両方でテストする
  （`CONSH_IMPL=conma` と `CONSH_IMPL=reference` で `consh/test/run_all.sh`）。
* 速くしただけ（動きは変えない）なら、高速版のテストだけでよい。

ここにファイルを書き写すときは、参照版のどの部分をどう速くしたかを、そのファイルの先頭に書く。

## 今の高速版

`consh_eval.se`、`consh_expand.se`、`consh_chan.se`、`consh_repl.se` を、次のように書き換えた（各ファイルの先頭にも書いてある）。動きは変えていない（consh/test が高速版と参照版の両方で通り、下のスクリプトの出力も同じ）。

* `Sh_get sh "key"` を `__Dict_lookup_or__ sh "key" __print_exit_error__` に、`num s` を `__Number_fromString__ __print_exit_error__ s` にした（関数の呼び出しを 1 つ減らす）。
* 条件が組み込み 1 つの関数（`__if__ (,() __is_null__ x) ...`）を、先に計算して渡す形（`__is_null__ x ,(test__) __if__ test__ ...`）にした（条件の関数を作って呼ぶ分を減らす）。
* `Func_lookup` を `__Cont_get__` を使わない形にし、`Sh_defined` で普通の変数を先に調べるようにした。
* 外部コマンド 1 つだけの `$( )`（`$(seq 1 10000)` など）の値を、1 段の LazyList で作るようにした（`Subst_lines_from`）。参照版は、util.se の `__LazyList_lines__`（改行を含む行の LazyList）を `Subst_lines` でもう一度包み、`__LazyList_lines_scan__` は行を取り出すたびに読んだ塊の残り全体を写す。高速版は、読んだ塊を 1024 文字ずつの断片に切り、断片の中を位置で進めて行を取り出す（`__String_find__` と `__String_substring__` は、呼ぶたびに文字列全体の文字数を数えるので、長い塊の中を位置で進めると、塊の長さの 2 乗の時間がかかる）。
* Stream から作る標準入力（シェルの標準入力、`< ファイル`、外部コマンドからのパイプ。`Input_stream`）も、同じ 1 段の LazyList で読むようにした。参照版は、`__LazyList_lines__` を `Lines_chomped` でもう一度包む。Stream は、それを開いた側が閉じるので、ここでは閉じない。
* `Subst_settle_os` で、まだ終わっていない `$( )` の値の先頭に `Pipe_cap` 個そろったこと（書き手がパイプに書けずに待っていること）を、記録（`"full"`）に覚えるようにした。参照版は、コマンドが終わるたびに値の先頭から `Pipe_cap` 個たどり直すので、出力がパイプに収まらない `$( )`（`$(seq 1 100000)`）を `for` 文で読むと、1 回ごとに約 760 ステップ余分にかかっていた。値の先頭は変わらず、評価した要素は残るので、一度そろえば、そのあとも同じ答えになる。

速さ（Apple M4、起動を含む、user + sys、3 回の最小。ステップ数は Rust 版の VM の `CONMA_PROFILE`）：

| スクリプト | ステップ数（参照版 → 高速版） | Rust 版の VM | 変換した VM |
|---|---|---|---|
| `for i in $(seq 1 10000); do n=$i; done` | 3.64M → 2.67M（-27%） | 0.161 → 0.125 秒 | 0.101 → 0.076 秒 |
| `n=0; for i in $(seq 1 100000); do n=$i; done; echo $n` | 112.6M → 33.2M（-71%） | 4.213 → 1.506 秒 | 2.006 → 0.680 秒 |
| `xs=$(seq 1 100)` の入れ子の for 文で `n=1` を 1 万回 | 4.54M → 4.34M（-4%） | 0.167 → 0.163 秒 | 0.078 → 0.072 秒 |
| `if defined i; then n=1; else n=2; fi` を 5000 回 | 6.47M → 4.38M（-32%） | 0.257 → 0.189 秒 | 0.127 → 0.084 秒 |
| 関数 `g $i`（`n=$x`）を 5000 回 | 5.17M → 4.41M（-15%） | 0.229 → 0.201 秒 | 0.111 → 0.094 秒 |
| 関数 `f $i`（`echo "x$a"`）を 3000 回 | 5.34M → 4.72M（-12%） | 0.238 → 0.218 秒 | 0.110 → 0.100 秒 |
| `echo $i` を 1 万回（`/dev/null` へ） | 7.88M → 6.49M（-18%） | 0.332 → 0.281 秒 | 0.170 → 0.145 秒 |
| `add $i x > (r)` を 3000 回 | 6.49M → 5.82M（-10%） | 0.287 → 0.266 秒 | 0.124 → 0.111 秒 |
| `y=$(f $i)` を 1000 回 | 3.75M → 3.39M（-10%） | 0.214 → 0.198 秒 | 0.116 → 0.109 秒 |
| `seq 1 100000 \| cnt`（`cnt` は `for x in $(stdin)` で数える関数） | 75.7M → 67.8M（-10%）※ | 3.59 → 3.18 秒 ※ | |

※ 標準入力の読み方を変える前の高速版との比較（Rust 版の VM のみ）。この場合の 1 行あたり約 680 ステップの多くは、関数どうしをつなぐチャネル（書き手が空きを待つ `Chan_wait_room` が 1 行に 2 回、コマンドごとの `$( )` の確かめが約 110 ステップなど）にかかる。書き手は、読み手が 1 つ取り出すたびに起こされて 1 つ書く。まとめて起こすようにすると減らせるが、書き手と読み手の動く順（標準エラー出力の並びなど）が変わり、Rust 版と同じ結果にならなくなるので、変えていない。

1 回の呼び出しで 1 ステップしか減らない書き換え（よく呼ばれる関数から `__Cont_get__` を取り除くなど）は、試したが効果がほとんどなかったので入れていない。
