# 安全な JavaScript のサブセット（SJS）の計画

JavaScript の安全なサブセット（以下 SJS。SafeJS）を、ConSh の算術評価 `(( ))` と算術置換 `$(( ))` の中に書けるようにする計画である。2026/11/9 に書き、2026/11/11 に、ユーザーと決めた `(( ))` の仕様（2）に合わせて書き直した。段階 A1 を作った（2026/11/11。consh/js/PLAN-ja.md の 3.23）。段階 A2 は、演算の型の確認のほかを作った（3.24）。

当面（段階 A）は SJS をホストの JavaScript で動かし、将来（段階 B）は SJS を ConMa に変換して VM の中で動かす。

## 1. 目的

1. **安全に JavaScript を書けるようにする**
    - 今の `js` と JS の文（consh/js/PLAN-ja.md の 2.1、2.5）は、ホストの JavaScript でコードをそのまま評価する。サンドボックスがないので、ConSh のスクリプトや入力を書く人は、ページや Node.js のプロセスの権限で何でもできる（consh/js/README-ja.md のセキュリティの注意）。そのため、2026/11/11 から、`js` と JS の文は既定では使えない（consh/js/PLAN-ja.md の 3.22）。
    - SJS は、計算に要るものだけを持つ JavaScript の下位互換の言語とする。段階 B では、SJS のコードは ConMa の VM の中だけで動き、ファイル、プロセス、ネットワーク、ホストの JavaScript には触れない。
2. **シェルと JavaScript を、ぶつからずに組み合わせる**
    - 今の JS の文は、先頭の語がコマンドでない文を JavaScript とするので、PATH の検索、関数の走査、シェルの文への戻しが要り、ConSh の予約語（`if`、`for`、`return` など）とも衝突した。
    - SJS は `(( ))` の中にだけ書くので、先頭の語の判定は要らず、括弧の中では JavaScript の `if`、`for`、`return` もそのまま書ける。
3. **ConMa を中間言語として確かめる**（段階 B）
    - REVIEW-ja.md（2026-11-06）の 5 は、ConMa が「より初心者向けの言語から変換して実行する中間言語」として使えることの証拠がまだないとし、小さな言語を 1 つ選んで ConMa に変換する処理を作ることを提案している。
    - SJS は、その小さな言語に当たる。関数、クロージャ、変更できる変数、例外、ループ、配列とオブジェクトを ConMa に変換することになり、手で書いた ConSh とは違う形のコードで ConMa を試せる。
    - 測るもの（REVIEW の 5 の提案どおり）：生成したコードの大きさ、性能、エラーの位置の対応（REVIEW の 1）。変換で困った点は、REVIEW の 1〜4、6（レコード）への答えにもなる。
    - 段階 B では、ホストの JavaScript を使わないので、ネイティブの VM で動く ConMa 版の ConSh でも、wasm 版でも、同じに動く。

## 2. ConSh での書き方（2026/11/11 に決めた仕様）

### 2.1. 文法

ConSh の文法（consh/PLAN-ja.md）に、次を足す。

```
単純文 = (コマンド | if文 | リストfor文 | reset文 | 算術評価) {スペース+ リダイレクト指定} | shift文 ;
語要素 = 引用文字列 | 変数参照 | コマンド置換 | 裸文字 {裸文字} | "\\" 文字 | 算術置換 ;
二重引用要素 = 変数参照 | コマンド置換 | "\\" (引用特殊文字 | 改行) | 文字 - 引用特殊文字 | "\\" (文字 - 引用特殊文字 - 改行) | 算術置換 ;
算術評価 = "((" 空白+ SJS式 空白+ "))" ;
算術置換 = "$" 算術評価 ;
```

- `((` の後と `))` の前には空白が要る。Bash の `$((1+2))`（空白なし）は構文エラーになる。
- SJS式の終わりは、文字の並びの ` ))` ではなく、JavaScript の字句解析（括弧の対応、文字列、テンプレート、コメント、正規表現）で決める。`(( " ))" ))` のように、文字列などの中の ` ))` では終わらない（今の JS の文の範囲の決め方、consh/js/PLAN-ja.md の 2.5 の 3 と同じ）。
- ConSh には `( … )` の書き方がないので、文の始めの `((` と、語の中の `$((` は、今は構文エラーである。そのため、この文法で意味が変わる今の書き方はない。`$((` は常に算術置換として読む。
- 将来の注意（SAFEJS-REVIEW-ja.md の 3.3 の 9）：ConSh にリストの入れ子の値（`x=((a b) c)`）を足すときは、値の位置の `((` が算術評価とぶつかる。今の算術評価は、文の始めと `$((` だけなので衝突しないが、値の位置に `((` を許すなら、算術評価の `((` の後の空白（必須）で見分けるなどの規則が要る。

### 2.2. 意味

1. **算術評価**：SJS式を評価する。
    - エラーなら、メッセージを標準エラーに出し、`$?` を 2 にする。
    - そうでなければ、戻り値の JavaScript の真偽で、真なら 0、偽なら 1 を `$?` に設定する（数の 0 は偽なので、Bash の `(( ))` と同じになる）。
    - 文の算術評価は、値を何も出さない（`(( 1+2 ))` は何も出さない）。
    - SJS式の中の代入は、シェルの変数ではなく、SJS変数を変える。例：`(( n = 1+2 ))` は SJS変数 `n` を 3 にする。
2. **算術置換**：SJS式の戻り値に置き換わる。
    - ほかの語要素があれば、文字列にして連結する（`echo a$(( 1+2 ))b` は `a3b`）。
    - 算術置換だけの語は、値のまま変数に入れるか、関数に渡す（`v=$(( n ))`）。外部コマンドには文字列にして渡す。
    - 配列とオブジェクトを文字列にする規則は、consh/js/PLAN-ja.md の 2.5 と同じにする。
    - エラーなら、その文を止め、`$?` を 2 にする。
3. **SJS関数の呼び出し**：コマンドの先頭の語の値が SJS の関数なら、その後の語を引数として関数を呼ぶ。
    - 例：`$(( (a, b) => Number(a) + Number(b) )) 1 2 2> (c)` で、`c` は 3。シェル変数 `f` に入れた関数は `$f 1 2` で呼ぶ。
    - 引数は、シェル関数の呼び出しと同じに扱う。ただし、配列は LazyList に合わせる。`a` が配列のとき、`$a` は要素を別々の引数にし、`${a}` は配列のまま 1 つの値にする。
    - 戻り値は**標準エラー**に出す。標準出力は `console.log` の出力に使う。
        - エラーのときは、受け取るのはエラーメッセージになるが、そのときの戻り値は使うべきでないので、それでよい。エラーでも値が欲しいときは、メッセージを読み飛ばす。
        - 戻り値を標準出力に出したいときは、リダイレクトを使う（`$f 1 2 2>&1 | g`）。デバッグで `console.log` を使うと、このとき結果が変わることに注意する。
        - ConSh の関数どうしの標準エラーにも、標準出力と同じく値がそのまま流れる（関数の中の `echo ${l} 1>&2` を `2> (c)` で受けると、`c` は要素の値を持つ。2026/11/11 に確かめた）。
        - 割り切った点（SAFEJS-REVIEW-ja.md の 3.2 の 6）：戻り値を受け取らずに呼ぶと、値が端末に、エラーと同じ所に出る。`2>/dev/null` で値を捨てると、エラーのメッセージも消える。値が要らないときは、`(( f(1, 2) ))` と算術評価で呼べば、何も出ない（$? は真偽）。
    - エラーなら `$?` を 2 にする。そうでなければ、戻り値の JavaScript の真偽で、真なら 0、偽なら 1 にする（算術評価と同じ。`if $isOk "$v"; then` と書ける）。
    - 先頭の語の値が、関数でない JS の値なら、エラーにして `$?` を 2 にする（文字列にしてコマンドの名前として探すことはしない）。
4. **シェル変数と SJS変数は共通にしない**
    - 同じ名前でも、独立した値を持つ。どちらも任意の JavaScript の値を持てる。
    - SJS変数からシェル変数へ：`v=$(( n ))`。
    - シェル変数から SJS変数へ：`(( n = $v ))`（7 の `$名前`）。SJS関数を呼んで引数で渡してもよい（`$(( (x) => { n = x } )) ${v}`）。
    - SJS変数は、シェル変数と同じく、関数、パイプラインの要素、`$( )`、`&` で写しになる。シェル関数の中で `(( n = 5 ))` としても、呼び出し側の `n` は変わらない。
    - **写しは浅い**（2026/11/11 に決めた。SAFEJS-REVIEW-ja.md の 3.1 の 2）：写すのは、名前から値への対応だけで、配列やオブジェクトの中身は写さない。そのため、シェル関数の中の `(( o.a = 1 ))` は、呼び出し側の `o` の中身も変える（JavaScript の `p = o; p.a = 1` と同じ）。段階 B でも、Dict を書き込みのときに写すこと（COW）はせず、同じ Dict を共有して、段階 A と同じ結果にする。
    - SJS関数の中の大域の SJS変数（関数の局所でない名前）は、**呼び出したときのシェルの SJS変数**を読み書きする。引数と関数の中の局所変数は、ふつうの JavaScript のクロージャどおりにする。JavaScript の大域変数がクロージャに写されないことと合う。これは動的なスコープなので、作った場所の変数を覚えるクロージャとは違う（SAFEJS-REVIEW-ja.md の 3.2 の 7）。例（consh/js/test/step6 の case1）：

      ```
      (( m = 5 ))
      (( g = () => m ))
      echo $(( g() ))                                        # 5
      function callg () { (( m = 50 )); echo $(( g() )) }    # 関数の中の m（写し）を変える
      callg                                                  # 50：g は、呼んだ所の m を読む
      echo $(( g() ))                                        # 5：外の m は変わっていない
      ```

    - 段階 A では、SJS変数をすべてホストに渡す（評価するコードに現れる名前だけでは、`$(( g() ))` のように、呼ぶ関数の中の名前を渡せない。consh/js/PLAN-ja.md の 3.23）。
5. **シェル関数と SJS関数は共通にしない**
    - シェル関数は数（終了状態）を返し、それを `$?` に設定する。SJS関数は任意の値を返す。
    - SJS からシェル関数は呼べない（SJS は計算だけをする）。
6. **Promise**：SJS関数が Promise を返したときは、Promise のまま変数に入れる。文字列にするときに、解決を待つ。算術評価の真偽では、Promise は真である（待たない）。ただし、段階 A では `async` と `await` を SJS の範囲の外にする（3.2）ので、SJS が Promise を作ることはない（ホストの `fetch` なども使えない）。Promise は、`async` を入れる段階 B5 からのことになる。
7. **`$名前` でシェル変数を読む**（2026/11/11 に足した。SAFEJS-REVIEW-ja.md の 3.2 の 5）
    - SJS式の中の `$` で始まる名前は、`$` を除いた名前のシェル変数を表す。`n=3; echo $(( $n + 1 ))` は、Bash と同じく `4` を出す。JavaScript では `$` は識別子の文字なので、SJS の字句と構文はそのままで、名前の解決だけを変える。
    - SJS変数の名前は `$` で始められない（`(( $x = 1 ))` は 7 の代入の規則に従い、`let $x` などの宣言はエラー）。そのため、`n` は SJS変数、`$n` はシェル変数と、見ればわかる。4 の「共通にしない」とも矛盾しない。
    - 値：String は文字列、リストの値（`$xs`）は配列、JS の値を持つ変数は、その値のままにする（consh/js/PLAN-ja.md の 2.5 の規則と同じ）。定義されていなければ、シェルの `$x` と同じエラーにする（`$?` は 2）。
    - **演算子の被演算子の `$名前` は数にする**（2026/11/11 に決めた）：次の演算子のすぐ左か右にある `$名前` は、`Number($名前)` の略記とする。`$名前` は JavaScript の識別子でなく SJS が決める書き方なので、こう定義しても、SJS は JavaScript の下位互換のままである。
        - 算術の `+`、`-`、`*`、`/`、`%`、`**`、単項の `-` と `+`、大小の比較の `<`、`<=`、`>`、`>=`。
        - `===` と `!==` は、もう一方の被演算子が数のリテラルのときだけ（`$n === 3` は数で、`$s === "abc"` は文字列で比べる）。
        - 括弧は透過する（`($n) + 1` も被演算子）。判定は構文だけで行う。
        - 数にならない値（数の書き方でない文字列、空文字列、配列など）は、`NaN` にせず、`not a number: $s` のようなエラー（`$?` は 2）にする。空文字列を 0 とする Bash とは違う。
        - そのほかの所（`` `${$n}` ``、`f($n)`、`(( s = $n ))` など）では、値のまま（String は文字列）にする。`n=007` なら、`$n + 1` は `8`、`` `${$n}` `` は `"007"` である。
        - 例：`n=3; echo $(( $n + 1 ))` は `4`、`(( $i < 10 ))` は数で比べる。`$n + "px"` は、数と文字列の `+` なのでエラーになり（3.1 の `+` の規則）、`` `${$n}px` `` と書く。
        - 変数を経由すると数にならない：`x = $n; x + 1` は、`x` が文字列なので、`+` の規則でエラーになる（`"31"` にはならない）。
    - SJS関数の中の `$名前` は、大域の SJS変数（4）と同じく、**呼び出したときのシェルの変数**を読む。段階 A では、ホストから VM のシェル変数をその場で問い合わせる手段がないので、呼ぶコード（`$(( g() ))`）に現れない `$名前` の値は、前もって渡しておく必要がある。そのため、構文解析のときに、スクリプト全体（対話モードではそれまでに読んだ入力すべて）の SJS式に現れる `$名前` を集めておき、評価のたびに、それらのうち定義されているシェル変数をすべて渡す（4.1）。
    - 真偽の判定は、数にしない（演算子の被演算子でないため）：`!$n`、`$n ? a : b`、`$n && x`、`if ($n)` は、`$n` の値のまま（String なら文字列）の JavaScript の真偽になる。そのため、`n=0` の `$n` は真である（空文字列でないので）。Bash の `(( n ))` は偽なので、数として判定するときは `$n !== 0` か `+$n` と書く。
    - `$1`、`$@`、`$#`、`${x}` などは、JavaScript の識別子でないので、SJS では書けない（必要なら後で決める）。

### 2.3. ほかに決めたこと

- **評価のエンジン**：当面（段階 A）は、SJS をホストの JavaScript で動かす。構文解析のとき、許可されていない関数呼び出しや名前があれば、エラーにする。これで抜け道がなくなったとは証明できない（5）。この確認の目的は、SJS の範囲を守り、将来 ConMa に変換したとき（段階 B）に同じに動くことを保証することである。
- **今の JS の文**：先頭の語で JavaScript と判定する文（consh/js/PLAN-ja.md の 2.5）は消す。
- **`js` コマンド**：DOM などのために残すが、既定では使えない。Node.js 版は環境変数 `CONSH_ENABLE_JS`、ブラウザ版はサーバの `config.json` で使えるようにする（consh/js/PLAN-ja.md の 3.22。作った）。
- **`CONSH_ENABLE_JS` の値**：`sjs` なら算術評価だけ、`js` なら算術評価と `js`（と JS の文）を使える。ないかほかの値なら、どちらもエラーにする（`$?` は 2）。段階 A の SJS もホストの JavaScript で動くので、有効にしたときだけ使う（consh/js/PLAN-ja.md の 3.22、3.23。作った）。
- **ネイティブ版**：段階 A では JavaScript がないので、どう扱うか（`((` を解析して、実行時に「SJS は使えない」というエラーにするかなど）は保留する。
- **取り消した案**：組み込みコマンド `sjs コード {引数}`、結果を変数に入れるリダイレクト `-> 変数名`、先頭の語で判定する SafeJS の文、ConSh の予約語にあたる JavaScript の文法を SJS から外す案（`(( ))` の中なら衝突しないので要らない）。

### 2.4. まだ決めていないこと

- 戻り値が `undefined` のとき、標準エラーに何も出さないか（今の `js` は出さない）。出すなら、`$(( (x) => { n = x } )) ${v}` のような値の受け渡しで `undefined` が出る。
- Promise を文字列にするときの待ち方（4.1）。
- 対話モードで、算術評価の値を表示するモードを設けるか。
- 文字列どうしの大小の比較（`"a" < "b"`）を、辞書順の比較として許すか（3.1 の演算の型）。許さなければ、文字列の比較には `a.localeCompare(b)` などを使う。
- 数の書き方（2.2 の 7 で `$名前` を数にするとき）：`3`、`-2.5`、`1e3`、`0x10` などのどれを認めるか。前後の空白を許すか（JavaScript の `Number()` は許す）。
- `$名前` への代入（`(( $n = 5 ))`）を許すか。最初は読むだけにし、代入は構文解析のときのエラーにする。許すなら、シェル変数を変える（Bash の `(( n = 5 ))` に近くなる）。
- Bash との違い（`(( n=1+2 ))` は Bash ではシェル変数を変える、`$((1+2))` は空白がないので構文エラー）を FOR-BASH-USERS.md に書くこと。
- 語の中の `$(( ))` のエラーで、文だけを止めること。段階 A1 では、ConSh の今のエラー（未定義の変数など）と同じく、スクリプトなら終了ステータス 2 で終え、対話モードならコマンド行を止める（consh/js/PLAN-ja.md の 3.23）。文だけを止めるには、文ごとに止める先を持つ仕組みが要る。

## 3. SJS の範囲

SJS は `(( ))` の中にだけ書くので、JavaScript の文法をそのまま使っても ConSh と衝突しない。範囲は、安全と、段階 B で ConMa に変換できることで決める。段階 A の構文解析の確認（2.3）も、この範囲を確かめる。

### 3.1. 入れるもの

- 値：数、文字列、真偽値、`null`、`undefined`、配列、プレーンなオブジェクト（`{a: 1}`）、関数
- シェル変数の参照：`$名前`（2.2 の 7。読むだけ）
- 式：算術（`+` は数どうしだけ。下の「演算の型」）、比較（`===`、`!==`。`==` は入れない）、論理（`&&`、`||`、`??`、`!`）、条件演算子、テンプレート文字列、メンバーの参照（`a.b`、`a[i]`）、呼び出し、配列とオブジェクトのリテラル、スプレッド（`...`）、分割代入（基本の形）、代入（SJS変数か、関数の局所変数）、コンマ演算子
- 関数：アロー関数と `function` 式。本体のブロックの中では、`let`、`const`、`if`/`else`、`while`、`for`（3 つの部分のもの、`for...of`）、`break`、`continue`、`return`、`throw`、`try`/`catch`/`finally` を書ける
- **演算の型**（2026/11/11 に決めた）：`+` は数どうしだけを足し、どちらかが数でなければ実行時のエラーにする。文字列の連結は、テンプレート文字列（`` `${a}${b}` ``）か `[a, b].join("")` で書く。`-`、`*`、`/`、`%`、`**`、単項の `-` と `+`、大小の比較も、被演算子が数でなければエラーにする（大小の比較は、文字列どうしなら、辞書順の比較として許すかを 2.4 で決める）。JavaScript の意味を変えず、紛らわしい組み合わせをエラーにするだけなので、SJS でエラーにならずに動いたコードは、JavaScript でも同じ結果になる。JavaScript から持ってきた `"a" + "b"` は、エラーで気付ける。
- 組み込み：`Math` の一部、`Number`、`String`、`JSON.stringify`、`JSON.parse`、`String` と `Array` のよく使うメソッド（`length`、`slice`、`indexOf`、`join`、`split`、`map`、`filter`、`reduce`、`forEach`、`some`、`every`、`find`、`push` など）、`console.log`（ConSh の標準出力）
- 後の段階（段階 B5）：ジェネレータ（`function*`、`yield`）、`async` 関数と `await`。段階 A では範囲の外（3.2）

### 3.2. 入れないもの

構文解析のときに「SJS では使えない」というエラーにする。

- `eval`、`Function`、`with`、`import`、モジュール
- 段階 A では、`async` と `await`、ジェネレータ（`yield`）：段階 A は、評価のたびに「今の SJS変数」を差し替えるので、`async` 関数が `await` の後で大域の名前を使うと、別の評価（別の VProc のシェル）の SJS変数を見てしまうため（SAFEJS-REVIEW-ja.md の 3.1 の 1。consh/js/PLAN-ja.md の 3.23 で入れた）
- プロトタイプ、`class`、`this`、`new`（組み込みの一部を除く）、getter/setter、`Proxy`、`Reflect`、`Symbol`、`Object.getPrototypeOf` などの反射の関数
- `constructor`、`__proto__`、`prototype` という名前のプロパティ（計算したキー `a[k]` では、実行時に確かめる。4.1）
- 暗黙の型変換（`==`。`+` で文字列を連結することも含め、数でない値の算術と、型の混ざった大小の比較は、実行時のエラーにする。3.1 の演算の型）
- 正規表現（最初は。要るなら、段階 B で ConMa に小さな実装を書く）
- ホストのもの：`document`、`window`、`globalThis`、`fetch`、`process`、`require`、`setTimeout` など。大域の名前は、SJS変数と許した組み込みだけにする。

## 4. 作り方

### 4.1. 段階 A：ホストの JavaScript で動かす

- **構文解析**（consh_parser.se）：文の始めの `((` と、語の中の `$((` を読み、SJS式の範囲を今の JS の字句解析（`Js_scan` など）で決める。構文木は、新しい節（たとえば文の `(arith 位置 コード 名前 ...)` と、語の中の `(arithsubst ...)`）にする。名前は、コードに現れる識別子で、SJS変数の受け渡しに使う。
- **演算の型の確認**（3.1）：段階 A でも段階 B と同じ結果にするため、算術の演算子と大小の比較を、被演算子の型を確かめる関数の呼び出しに書き換える（`a + b` を `__sjs_add(a, b)` に、`a += b` を `a = __sjs_add(a, b)` に、など）。演算子の被演算子の `$名前`（2.2 の 7）は、数に直す関数（エラーなら `not a number`）の呼び出しにする。演算子の優先順位どおりに書き換える（`a + b * c` は `__sjs_add(a, __sjs_mul(b, c))`）には、今の字句を並べ替えるだけの書き換え（`sjsCheck`）では足りず、SJS の式の構文解析器（Pratt 法などの小さなもの）が要る。conma.js に書き、段階 B の変換器の試作にもする。
- **範囲の確認**：構文解析のとき、3.2 の名前、構文、プロパティがあればエラーにする。計算したキーのメンバー参照（`a[k]`）は、`constructor`、`__proto__`、`prototype` を拒む関数の呼び出しに書き換える（今もコードを書き換えている。conma.js の `rewriteDeclarations`）。
- **`$名前`**（2.2 の 7）：構文解析で、`$` で始まる名前を、SJS変数の名前とは別に集める。集めるのは、評価するコードだけでなく、スクリプト全体（対話モードでは、それまでに読んだ入力すべて）の SJS式からである（SJS関数の中の `$名前` は、それを呼ぶコードに現れないため）。評価のたびに、それらのうち定義されているシェル変数の値を、今の JS の文がシェル変数を渡すのと同じ形でホストに渡し、ホストは `$名前` をその値に束縛する（代入はさせない）。`$` で始まる名前の宣言と、（代入を許さないなら）代入は、構文解析のときのエラーにする。
- **SJS変数**：ConSh の文脈に、名前から値への Dict（たとえば `sh` の `"sjsvars"`）を置き、シェル変数の `"vars"` と同じ所で写す。値は、今の JS の値と同じく、ホストの表の番号（`#n`）か、プリミティブの値そのものにする（consh/js/PLAN-ja.md の 2.5 の 4）。評価のたびに、コードに現れる名前の値だけをホストに渡し、代入された名前の値を受け取る（今の JS の文と同じ）。
- **呼び出したときの SJS変数**：SJS関数の中の大域の名前は、作ったときの `with` のスコープではなく、呼び出したときの SJS変数を引く。ホストは、評価や呼び出しのたびに「今の SJS変数」を差し替え、関数の大域の参照はその Proxy を通す。
- **JS の値の寿命**：SJS変数の写しが JS の値を持つ間は、ホストの表から消せない。今の「値を作った呼び出しが解放する」規則（consh/js/PLAN-ja.md の 3.18）では足りず、写しが捨てられたことを VM から知る仕組みが要る（7）。
- **Promise を文字列にする**（段階 B5 から。段階 A では SJS が Promise を作らない。2.2 の 6）：今、`$v` を文字列にする `__JS_value__` は同期のホストの関数なので、Promise を待てない（Node.js 版とページで動かす版では、VM と同じスレッドで待つことになる）。Promise の値を文字列にするときだけ、`__JS_call__`（ストリームで答える非同期の呼び出し）を使えば、VProc がストリームを読んで待つので、どの版でも待てる。`Value_force` は継続を渡す形なので、切り替えられる。
- **今の JS の文を消す**：consh_parser.se の `Ps_js` などと、consh_jsstmt.se の JS の文の評価、conma.js の `evaluateStatement` のうち `js` に要らない部分を消す。consh/js/test の step5 を `(( ))` のテストに書き直す。

### 4.2. 段階 B：ConMa に変換して動かす

1. **変換か、解釈か**
    - (推奨) SJS のコードを ConMa のソースに変換し、モジュールにして動かす。中間言語の検証には、変換したコードを VM で動かす必要がある。
    - SJS のインタプリタを ConMa で書く案は取らない。作るのは楽だが、それは「ConMa で書いたプログラム」であり、中間言語の検証にならない。
2. **変換器を何で書くか**
    - (推奨) ConMa で書く。ConSh の中（ネイティブ版、Node.js、ブラウザ）で変換でき、ConMa の front end（include/ の lexer.se、parser.se など）や consh_parser.se と同じく、ConMa で書いた構文解析の例が増える。
    - 最初の試作だけ Python で書き、変換の規則を固めてから ConMa に移す、という順も考えられる。
3. **配列とオブジェクトの表し方**
    - ConMa には、添字で読み書きできる列がない（MSeq は先頭からしか取れない）。JavaScript の配列には、添字の読み書きと長さが要る。
    - 案 A（推奨）：配列もオブジェクトも Dict で表す。配列は、数のキーと `"length"` を持つ Dict にする。プリミティブを足さずに済み、REVIEW の 6（レコードがない）を考える材料にもなる。遅ければ、案 B に進む。
    - 案 B：添字で読み書きできる列のプリミティブ（`__Vec_*__` など）を VM に足す。性能の差を測ってから決める。
4. **値**：段階 B では、SJS の値は ConMa の値になる（数は Number、配列とオブジェクトは Dict）。シェル変数と SJS変数にもそのまま入るので、ホストの表と、その解放の問題はなくなる。

変換の対応：

| SJS | ConMa |
|---|---|
| 関数 `(a, b) => { ... }` | `,(a b) __Cont_get__ ,(return) ...`。クロージャは ConMa のクロージャ |
| `return x` | `return x` |
| 再代入される変数（`let x`、引数） | Ref に入れる（代入の変換。再代入されない変数は、そのまま束縛にする） |
| SJS変数（大域の名前） | 呼び出したときのシェルの `"sjsvars"` の Dict を読み書きする実行時の関数 |
| `$名前`（シェル変数） | 呼び出したときのシェルの変数を引く実行時の関数（ConSh の `$x` と同じ引き方。String を数にするなら、その変換も） |
| `if`、条件演算子、`&&`、`\|\|`、`??` | `__if_then_else__` など |
| `+` などの算術、大小の比較 | 被演算子が Number か確かめる実行時の関数（Number どうしなら `__Number_add__` など。変換器が両方 Number とわかるときは、直接プリミティブにする） |
| 演算子の被演算子の `$名前` | シェル変数を引き、Number に直す実行時の関数（直せなければ `not a number` のエラー） |
| `while`、`for` | ループの本体を局所の関数にし、`break` はループの脱出の継続、`continue` はその回の脱出の継続にする（ConSh の `for` と同じ考え方） |
| `throw`、`try`/`catch` | 例外の受け手の継続を、PDict（VProc ごとの Dict）のスタックに置く。`throw` は一番上の受け手を呼ぶ。プリミティブの `onError` も受け手に渡す |
| `finally` | 脱出（`return`、`break`、例外）の継続を包んで、先に本体を実行する |
| 配列、オブジェクト | Dict（上の 3） |
| ジェネレータ | 限定継続（ConSh の `reset`/`shift` と同じく、CChain のプリミティブで作る）か、VProc とチャネル |
| `async`/`await` | VProc と `__Ref_wait_change__` |
| `console.log` | ConSh が渡す出力の関数を呼ぶ |

- 名前：SJS の識別子は、ConMa の名前と重ならないように、前に印を付ける（`js_x` など）。利用者は `__OS_open__` のようなプリミティブの名前を書けない。
- 実行時の支え：値の型を確かめる関数、演算、組み込みのメソッドは、ConMa で書いたライブラリ（たとえば `consh/include/sjs_rt.se`）にまとめる。
- エラーの位置：生成する ConMa のソースは、SJS の 1 つの文を 1 か所にまとめ、SJS の行と桁を、実行時のエラーに出せるようにする。どこまでできるかを測る（REVIEW の 1）。
- 動かし方：変換したソースをモジュールにする。ネイティブ版は `conma build`（VM に埋め込んだ ConMa の front end）、Node.js の wasm 版は `host_build_module`（consh/js/PLAN-ja.md の 3.10）を使う。ブラウザ版には今それがない（`includer failed`）ので、ページか Worker で、もう 1 つの VM のインスタンスに `vm/frontend.module.se` を動かす形を作る。同じコードを何度も動かすときのために、変換とモジュールを、コードの文字列で覚えておく。

### 4.3. 自分が戻るためだけに使う継続の最適化

ConMa の関数が、最初に `__Cont_get__` で取った継続（`return`）を自分が戻るためだけに使うなら、継続の値を作らずに CChain で戻る、という最適化の計画は、SJS だけでなく ConMa 全体のことなので、docs/ROADMAP.md の「Planned: returning without making the escape continuation」に移した（SAFEJS-REVIEW-ja.md の 3.1.4）。移すときに、レビューの指摘どおり、その関数の実行中に CChain を取り出さないこと（ConSh の `shift` は LCont を取り出して別の CChain の上で呼ぶので、`return` の時の CChain が `__Cont_get__` の時と同じにならない）を条件に足し、最適化を、継続を取り出さないとわかっているコード（変換器が出した SJS のコードなど）に限ることにした。

## 5. 安全性

- **段階 A は安全の境界ではない**：ホストの JavaScript で動かすので、構文解析の確認（3.2）をすり抜けるコードがあれば、ページや Node.js のプロセスの権限で動く。たとえば、名前を見るだけの確認では `[]["constructor"]["constructor"]("任意のコード")()` で `Function` に届く。計算したキーの書き換えと、大域の名前と反射の関数の制限で、知られている抜け道は防ぐが、なくなったとは証明できない。そのため、段階 A の間は、consh/js/README-ja.md のセキュリティの注意をそのまま残す。
- **段階 B で安全になる**：SJS のプログラムが呼べるのは、変換器が出したコードと、実行時の支えのライブラリだけである。変換器は、`__OS_*__`、`__JS_call__`、`__VProc_spawn__` などを出さない。SJS からシェル関数は呼べない（2.2 の 5）ので、外とつながるのは、引数と戻り値、SJS変数、`console.log` だけである。
- **ホストの JavaScript を確実に止める**：段階 B の後、`js` を使わないサーバでは、Content-Security-Policy で `'unsafe-eval'` を許さなければ（WebAssembly のための `'wasm-unsafe-eval'` だけを許す）、ブラウザが `Function` と `eval` を止める。段階 A の SJS もホストの `Function` を使うので、それまでは使えない。
- 終わらないループは、Ctrl-C で止める（ConSh の今の仕組み）。使うメモリと時間の上限は、まだない（7）。

## 7. 未解決の点とリスク

- **JS の値の寿命（段階 A）**：SJS変数の写しが持つ JS の値を、いつホストの表から消すか（4.1）。今の JS の値と同じく、関数の局所の値は循環の回収まで残る（consh/js/PLAN-ja.md の 4）。
- **範囲の確認の抜け道（段階 A）**：5 のとおり、確認は証明にならない。見つかった抜け道は、確認か書き換えに足す。
- **確認が拒否リストに近い（段階 A）**（SAFEJS-REVIEW-ja.md の 3.3 の 8）：今の確認は、拒否するプロパティ名と、許可する大域の名前を組み合わせている。メソッドの名前も、許可するものだけにすれば（`.call`、`.apply`、`.bind` を含めて決める）、抜け道は減るが、使える書き方も減る。式の構文解析器（4.1）を作るときに、許可リストにするかを決める。
- **性能**：ConMa の VM はホストの JavaScript よりずっと遅い（変換した VM でも CPython と同じくらい。bench/）。段階 B の SJS は、速さより安全さと検証のためのものとする。
- **数の意味**：ConMa の Number と JavaScript の数（IEEE 754 の倍精度）の違い（整数の扱い、`NaN`、`-0`、文字列への変換）を、どこまで合わせるか。段階 A と段階 B で結果が変わらないようにする必要がある。
- **文字列**：JavaScript の文字列は UTF-16 の列で、ConMa の String とは長さと添字の意味が違うことがある（サロゲートペア）。
- **資源の上限**：無限の再帰やメモリの使い過ぎを止める仕組みがない。VProc ごとのステップ数やメモリの上限を、VM に足すかどうか。
- **変換のたびの費用**：`(( ))` を評価するたびに変換とモジュールの作成をすると遅い（ConSh のモジュールは作るのに数秒かかる。小さなモジュールならずっと速いはずだが、測る必要がある）。4.2 の覚えておく仕組みで足りるか。
