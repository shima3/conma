# 安全な JavaScript のサブセット（SafeJS）の計画

JavaScript の安全なサブセット（以下 SafeJS）を ConMa に変換し、ConSh の中で動かせるようにする計画である。2026/11/9 に書いた。まだ何も作っていない。

## 1. 目的

1. **安全に JavaScript を書けるようにする**
    - 今の `js` と JS の文（consh/js/PLAN-ja.md の 2.1、2.5）は、ホストの JavaScript でコードをそのまま評価する。サンドボックスがないので、ConSh のスクリプトや入力を書く人は、ページや Node.js のプロセスの権限で何でもできる（consh/js/README-ja.md のセキュリティの注意）。
    - SafeJS のコードは、ConMa の VM の中だけで動く。使えるのは、ConSh が渡した機能（シェルの変数、標準入出力、許した関数）だけである。
2. **ConMa を中間言語として確かめる**
    - REVIEW-ja.md（2026-11-06）の 5 は、ConMa が「より初心者向けの言語から変換して実行する中間言語」として使えることの証拠がまだないとし、小さな言語を 1 つ選んで ConMa に変換する処理を作ることを提案している。
    - SafeJS は、その小さな言語に当たる。関数、クロージャ、変更できる変数、例外、ループ、配列とオブジェクトを ConMa に変換することになり、手で書いた ConSh とは違う形のコードで ConMa を試せる。
    - 測るもの（REVIEW の 5 の提案どおり）：生成したコードの大きさ、性能、エラーの位置の対応（REVIEW の 1）。変換で困った点は、REVIEW の 1〜4、6（レコード）への答えにもなる。
3. **どの版でも同じに動く**
    - ホストの JavaScript を使わないので、ネイティブの VM（Rust 版、Python 版）で動く ConMa 版の ConSh でも、wasm 版でも、同じに動く。Rust 版の ConSh（consh/rust）には入れない（ConMa の検証にならないため）。

## 2. 決めること（推奨の案）

1. **変換か、解釈か**
    - (推奨) SafeJS のコードを ConMa のソースに変換し、モジュールにして動かす。中間言語の検証には、変換したコードを VM で動かす必要がある。
    - SafeJS のインタプリタを ConMa で書く案は取らない。作るのは楽だが、それは「ConMa で書いたプログラム」であり、中間言語の検証にならない。
2. **変換器を何で書くか**
    - (推奨) ConMa で書く。ConSh の中（ネイティブ版、Node.js、ブラウザ）で変換でき、ConMa の front end（include/ の lexer.se、parser.se など）や consh_parser.se と同じく、ConMa で書いた構文解析の例が増える。
    - Python か Rust で書く案は、作るのは楽だが、ConSh の中で使えず（ブラウザで動かない）、確かめられることも減る。最初の試作だけ Python で書き、変換の規則を固めてから ConMa に移す、という順も考えられる。
3. **ConSh への入れ方**
    - (推奨) 新しい組み込みコマンド `sjs` にする。今の `js` と JS の文はそのまま残す（ホストの JavaScript。安全でない）。
    - 書き方は `js` に合わせる：`sjs [変数名=] コード {引数}`。コードは式か、文の並び（`return` の値が結果）。結果の出し方と、変数に入れる値は、`js` の 2.1 の 5、6 と同じ規則にする。
    - JS の文の既定を SafeJS に切り替えるか（安全な既定）は、SafeJS ができてから決める。
4. **配列とオブジェクトの表し方**
    - ConMa には、添字で読み書きできる列がない（MSeq は先頭からしか取れない）。JavaScript の配列には、添字の読み書きと長さが要る。
    - 案 A（推奨）：配列もオブジェクトも Dict で表す。配列は、数のキーと `"length"` を持つ Dict にする。プリミティブを足さずに済み、REVIEW の 6（レコードがない）を考える材料にもなる。遅ければ、案 B に進む。
    - 案 B：添字で読み書きできる列のプリミティブ（`__Vec_*__` など）を VM に足す。性能の差を測ってから決める。

## 3. 言語の範囲

### 3.1. 入れるもの

段階ごとに広げる（6）。

- 値：数（ConMa の Number）、文字列、真偽値、`null`、`undefined`、配列、プレーンなオブジェクト（`{a: 1}`）、関数
- 宣言：`let`、`const`（再代入を変換のときにエラーにする）、関数の宣言、アロー関数
- 式：算術、比較（`===`、`!==` だけ。`==` は入れない）、論理（`&&`、`||`、`??`、`!`）、条件演算子、テンプレート文字列、メンバーの参照（`a.b`、`a[i]`）、呼び出し、配列とオブジェクトのリテラル、スプレッド（`...`）、分割代入（基本の形）
- 文：`if`、`while`、`for`（3 つの部分のもの）、`for...of`、`break`、`continue`、`return`、`throw`、`try`/`catch`/`finally`、ブロック
- 組み込み：`Math` の一部、`String` と `Array` のよく使うメソッド（`length`、`slice`、`indexOf`、`join`、`split`、`map`、`filter`、`reduce`、`push` など）、`JSON.stringify`、`JSON.parse`、`console.log`（ConSh の標準出力）
- 後の段階：ジェネレータ（`function*`、`yield`）、`async`/`await`

### 3.2. 入れないもの

変換のときに「SafeJS では使えない」という構文エラーにする。

- `eval`、`Function`、`with`、`import`、`export`、モジュール
- プロトタイプ、`class`、`this`、`new`（組み込みの一部を除く）、getter/setter、`Proxy`、`Reflect`、`Symbol`
- 暗黙の型変換の多く（`==`、文字列と数の `+` 以外の混ぜた演算は、実行時のエラーにする）
- 正規表現（最初は。要るなら、後で ConMa で小さな実装を書く）
- ホストのもの：`document`、`window`、`fetch`、`process`、`require` など。名前は、SafeJS の大域にないので、参照すると ReferenceError になる。

## 4. 変換の方針

ConMa の関数はすべて継続を渡す形で呼ばれ（SPEC.md）、`__Cont_get__` で関数の脱出の継続が取れる。これを使って、JavaScript の制御を表す。

| SafeJS | ConMa |
|---|---|
| 関数 `function f (a, b) { ... }` | `(define f ,(a b) __Cont_get__ ,(return) ...)`。クロージャは ConMa のクロージャ |
| `return x` | `return x` |
| 再代入される変数（`let x`、引数） | Ref に入れる（代入の変換。再代入されない変数は、そのまま束縛にする） |
| `if`、条件演算子、`&&`、`||` | `__if_then_else__` など |
| `while`、`for` | ループの本体を局所の関数にし、`break` はループの脱出の継続、`continue` はその回の脱出の継続にする（ConSh の `for` と同じ考え方） |
| `throw`、`try`/`catch` | 例外の受け手の継続を、PDict（VProc ごとの Dict）のスタックに置く。`throw` は一番上の受け手を呼ぶ。プリミティブの `onError` も受け手に渡す |
| `finally` | 脱出（`return`、`break`、例外）の継続を包んで、先に本体を実行する |
| 配列、オブジェクト | Dict（2 の 4） |
| ジェネレータ | 限定継続（ConSh の `reset`/`shift` と同じく、CChain のプリミティブで作る）か、VProc とチャネル |
| `async`/`await` | VProc と `__Ref_wait_change__` |
| `console.log` | ConSh が渡す出力の関数を呼ぶ |

- 名前：SafeJS の識別子は、ConMa の名前と重ならないように、前に印を付ける（`js_x` など）。利用者は `__OS_open__` のようなプリミティブの名前を書けない。
- 実行時の支え：値の型を確かめる関数、演算、組み込みのメソッドは、ConMa で書いたライブラリ（たとえば `consh/include/safejs_rt.se`）にまとめる。
- エラーの位置：生成する ConMa のソースは、SafeJS の 1 つの文を 1 か所にまとめ、SafeJS の行と桁を、実行時のエラー（`throw` されたまま受け手がない例外）に出せるようにする。どこまでできるかを測る（REVIEW の 1）。

## 5. ConSh での動かし方と安全性

1. `sjs` は、コードを SafeJS の構文解析器で読み、ConMa のソースに変換する。
2. ソースをモジュールにして、`__VProc_spawn__` で新しい VProc で動かす。
    - ネイティブ版は、今と同じく `conma build`（VM に埋め込んだ ConMa の front end）でモジュールを作る。Node.js の wasm 版は `host_build_module`（consh/js/PLAN-ja.md の 3.10）を使う。
    - ブラウザ版には今それがない（`includer failed`）。ページか Worker で、もう 1 つの VM のインスタンスに `vm/frontend.module.se` を動かす形を作る（Node.js の vm-node.js と同じ）。
    - 同じコードを何度も動かすときのために、変換とモジュールを、コードの文字列で覚えておく。
3. ConSh は、`__VProc_spawn__` の引数として、SafeJS のプログラムに渡す機能（シェルの変数を読む関数、標準入出力、`console.log`、結果を返す関数）を渡す。`__VProc_spawn__` は、親が渡したクロージャを親のプログラムのまま呼べるので（docs/PRIMITIVES.md）、機能は ConSh 側の関数として渡せる。
4. 安全性の考え方：
    - SafeJS のプログラムが呼べるのは、変換器が出したコードと、実行時の支えのライブラリと、渡された関数だけである。変換器は、`__OS_*__`、`__JS_call__`、`__VProc_spawn__` などを出さない。
    - そのため、ファイル、プロセス、ネットワーク、ホストの JavaScript には触れない。渡す機能を増やすときは、ConSh の側で一つずつ決める（たとえば、許したディレクトリのファイルだけを読む関数）。
    - 終わらないループは、Ctrl-C でその VProc を止める（ConSh の今の仕組み）。使うメモリと時間の上限は、まだない（7）。

## 6. 段階

各段階は、そこまでのテストが通り、ConSh のテスト（consh/test、consh/js/test）がすべて通ることで終わりとする。

| 段階 | 内容 | 確かめ方 |
|---|---|---|
| 1 | 変換器の土台：数、文字列、真偽値、`let`/`const`、関数とクロージャ、`if`、`while`、`return`、`console.log`。ConMa で書き、ネイティブ版で `conma build` して動かす | 小さなプログラムの出力を、Node.js で動かした同じコードの出力と比べるテスト |
| 2 | 配列とオブジェクト（Dict）、`for`、`for...of`、`break`、`continue`、組み込みのメソッドの一部、テンプレート文字列 | 同上。配列の操作の速さを測る（2 の 4 の判断） |
| 3 | `throw`、`try`/`catch`/`finally`、実行時のエラーと位置 | 例外のテスト。エラーに SafeJS の行と桁が出ること |
| 4 | ConSh の組み込みコマンド `sjs`（ネイティブ版と Node.js の wasm 版）。引数、標準入力、結果、変数に入れる値 | consh/test に `sjs` のテスト（ネイティブ版と wasm 版で同じログ） |
| 5 | ジェネレータ、`async`/`await` | イテレータの結果が `js` と同じ規則で出ること |
| 6 | ブラウザ版（ページか Worker で front end を動かす） | ブラウザで `sjs` が動くこと |
| 7 | 測る：生成したコードの大きさ、性能（ホストの JavaScript、手で書いた ConMa と比べて）、エラーの位置の対応。結果を REVIEW-ja.md の 5 への答えとしてまとめる | 表にする |

## 7. 未解決の点とリスク

- **性能**：ConMa の VM はホストの JavaScript よりずっと遅い（変換した VM でも CPython と同じくらい。bench/）。SafeJS は、速さより安全さと検証のためのものとする。
- **数の意味**：ConMa の Number と JavaScript の数（IEEE 754 の倍精度）の違い（整数の扱い、`NaN`、`-0`、文字列への変換）を、どこまで合わせるか。
- **文字列**：JavaScript の文字列は UTF-16 の列で、ConMa の String とは長さと添字の意味が違うことがある（サロゲートペア）。
- **資源の上限**：無限の再帰やメモリの使い過ぎを止める仕組みがない。VProc ごとのステップ数やメモリの上限を、VM に足すかどうか。
- **変換のたびの費用**：`sjs` を呼ぶたびに変換とモジュールの作成をすると遅い（ConSh のモジュールは作るのに数秒かかる。小さなモジュールならずっと速いはずだが、測る必要がある）。2 の覚えておく仕組みで足りるか。
- **JS の文の既定**：SafeJS を JS の文の既定にすると、DOM などを使う今の使い方ができなくなる。既定を変えるか、変数などで選べるようにするかは、段階 4 の後に決める。
