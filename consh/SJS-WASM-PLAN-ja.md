# SJS の数の関数を WebAssembly にする計画

SJS（consh/SAFEJS-PLAN-ja.md、consh/sjs/README-ja.md）のうち、数だけを扱う関数を WebAssembly（以下 wasm）にして、wasm 版の VM（consh/js）のホストで動かす計画である。2026-11-14 に書いた。

**状態**：段階 1〜4 を作った（2026-11-14。段階 1 は docs/ROADMAP.md の Step 43 と test/fast7、段階 2 は 13 と consh/sjs/test/step9、段階 3 は 14 と consh/sjs/test/step10、段階 4 は 15 と consh/test/step21 の case9、段階 5 は 16）。計画した段階は、すべて作った。次は配列（9）。2026-11-14 に、ユーザーと 6 つのことを決めた（10）：最初は数の関数だけを対象にし、後で配列も対象にする（9）。wasm 版を選ぶのは、どのモードでも呼ぶとき（5.2）。SJS の `-0` を JavaScript に合わせる（11。同じ日に作った）。燃料とやり直しの方式（5.5）。`Value::Wasm` を足すこと（5.3）。`__Wasm_compile__` と `__Wasm_call__` を ConMa のプログラムから使えるようにすること（5.3）。決めることは残っていないので、段階 1（8）から作れる。

## 1. 目的

1. **数の計算を速くする**
    - 段階 B の SJS は、手で書いた ConMa の 4.8〜9.2 倍のステップがかかる。nbody 2000 は 1.10 秒で、手で書いた ConMa は 0.10 秒、CPython は 0.024 秒である（consh/sjs/README-ja.md の「速さ」、Rust 版の VM）。
    - wasm にした部分は、ホストの JIT（V8、JavaScriptCore）で機械語になる。内側のループと再帰は、ネイティブに近い速さになる見込みである。
2. **安全なまま速くする**
    - 段階 A（ホストの JavaScript で評価する）なら速いが、安全の境界にならない（SAFEJS-PLAN-ja.md の 5）。
    - wasm のモジュールは、import として渡したものにしか触れない。この計画のモジュールには何も import させない（6）ので、数を受け取って数を返すことしかできず、`CONSH_ENABLE_JS` は要らない。
3. **ConMa を中間言語として試す、もう 1 つの例にする**
    - ConMa で書いたプログラム（変換器 sjs_gen.se）が、ConMa の VM と別の機械（wasm）のコードを出し、VM がその 2 つを選んで使う。

## 2. 方針

* **SJS の全部は変換しない**。オブジェクト、文字列、ジェネレータ、async、例外を wasm で作ると、もう 1 つの JavaScript の処理系になる（GC のある値、継続の代わりの CPS 変換か stack switching、ConSh とのつながり）。最初の対象は、3 の「数の関数」だけにする。配列は、その後で対象にする（9）。
* **同じ関数を 2 通りに変換する**。数の関数も、今までどおり ConMa に変換する（以下「ConMa 版」）。それに加えて、wasm の関数（以下「wasm 版」）も作る。呼び出すたびに、実行時の支えが、引数を見てどちらを動かすかを選ぶ（5.2）。
* **2 つの版の結果を同じにする**。wasm の f64 の演算は、IEEE 754 のとおりの丸めで、勝手に融合積和（FMA）にしない。Rust の f64 の演算（VM の `__Number_add__` など）も同じである。そのため、ConMa 版と同じ式で求めれば、結果は同じになる。
* **SJS は JavaScript に合わせる**（2026-11-14 に決めた）。今の ConMa 版は、`-0` を `0` と区別しないので、`1 / -0`、`Math.max(-0, 0)` などが JavaScript と違う。wasm 版より先に、ConMa 版を JavaScript に合わせる（11）。そうすれば、wasm 版は `f64.div`、`f64.max` などをそのまま使える（4）。
* **数の関数は、副作用がなく、やり直せる**。数の関数は、引数と自分の局所の変数しか書き換えず、出力もしない（3.2）。そのため、wasm 版を途中で捨てて、同じ引数で ConMa 版を始めから動かしても、結果は同じになる。燃料が切れたとき、スタックがあふれたとき、Ctrl-C のときは、この性質を使う（5.5）。
* **wasm を使えない VM では、ConMa 版だけで動く**。ネイティブの VM、変換版の VM、Python の VM では、wasm のモジュールを作るプリミティブが onError を呼ぶので、実行時の支えは ConMa 版だけを使う。出力は同じなので、どの VM でも同じテストが通る。

## 3. 数の関数

### 3.1. 書けるもの

次のものだけでできている関数（`function` の宣言と式、アロー関数）を、数の関数とする。

* **引数**：名前だけ（既定値、残りの引数、分割代入はない）。引数への代入はよい（loop.sjs の `n -= 1`）。
* **値**：数のリテラル、引数、局所の変数（`let`、`const`）。外の名前は、数のリテラルで初期化した `const` で、宣言より前に読まれないもの（今の `Gen_plain_marks` が Ref を作らないもの）だけ。wasm では定数にする。
* **式**：`+ - * / %`、比較（`< <= > >=`、数どうしの `===`、`!==`）、ビット演算（`& | ^ ~ << >> >>>`）、単項の `-`、`+`、`!`、`++`、`--`、算術とビット演算の複合の代入、条件演算子。`&&` と `||` は、両辺が真偽値と分かるとき（比較の結果など）だけ。
* **呼び出し**：ほかの数の関数（5.1 の条件を満たす名前で呼ぶもの。自分も含む）と、`Math.floor`、`ceil`、`round`、`trunc`、`abs`、`sqrt`、`sign`、`max`、`min`（引数の数は決まっていること）、`Math.PI`。
* **文**：`let`、`const`、`if`、`while`、`do...while`、`for`（初期化、条件、更新の形）、ラベルのない `break` と `continue`、`return 式`、式の文、ブロック。
* **型**：局所の変数と戻り値は、どれも数（f64）。真偽値は条件の中だけにあり、変数には入れない（入れる関数は数の関数にしない）。

### 3.2. 数の関数にしないもの

上に挙げていないものを 1 つでも使う関数は、数の関数にしない（今までどおり ConMa 版だけ）。特に次のものである。

* 文字列、配列、オブジェクト、`null`、`undefined` を作るか、読む。`console.log`。
* 外の変数を書き換える。外の `let` や、引数で初期化した外の `const` を読む（クロージャの変数。値が呼び出しごとに違うので、定数にできない）。
* 関数を作る（関数の中の関数、アロー関数）。`throw`、`try`、`yield`、`await`。
* 最後まで来て `return` しないことがある（値が `undefined` になる）。最後の文が `return` か、出口のないループであることを、変換器が確かめる。
* `**`（ConMa 版の求め方が決まっていないので、同じ結果を保証できない。SAFEJS-PLAN-ja.md の 8）。

### 3.3. 例

* consh/sjs/bench/loop.sjs の `loop`、fib.sjs の `fib` は、数の関数になる。
* nbody.sjs の `advance` と `energy` は、配列（`b[X]`）と `for...of` の分割代入を使うので、数の関数にならない。配列を入れるかどうかは 9 で扱う。

## 4. ConMa 版と同じ意味にする

ConMa 版は、11 で JavaScript に合わせた後のものとする。

| SJS | ConMa 版（11 の後） | wasm 版 |
|---|---|---|
| `+ - *` | `__Number_add__` など | `f64.add` など |
| `/` | `Sjs_div`：JavaScript と同じ（`1 / -0` は `-Infinity`） | `f64.div` |
| `%` | `Sjs_mod`：割る数が 0 なら `NaN`。割られる数が 0 か、割る数が無限大なら、割られる数。ほかは `a - b * Sjs_trunc(a / b)` で、結果が 0 なら割られる数の符号を付ける | 同じ手順（`f64.div`、`f64.trunc`、`f64.mul`、`f64.sub`、`f64.copysign`）。wasm には f64 の剰余がない。大きな数で下の桁が JavaScript と違うことは、今の ConMa 版と同じ（consh/sjs/README-ja.md） |
| `< >` | 差が負か（`__Number_subtract__`、`__Number_is_negative__`。`Gen_arith`、`Sjs_less`） | `f64.lt`、`f64.gt`。違う 2 つの有限の数の差は 0 にならず、無限大どうしと NaN の差は NaN（負でない）なので、同じ結果になる |
| `<= >=` | 今の変換器の手順 | 今の手順と同じ結果になる wasm の命令を、作るときに決める |
| `=== !==`（数どうし） | | `f64.eq`、`f64.ne`（`NaN !== NaN`、`0 === -0`） |
| ビット演算 | `__Number_and32__` など（docs/BITWISE-PLAN-ja.md）。ToInt32 は NaN と無限大を 0 にし、0 の方へ切り捨て、2^32 で割った余り | ToInt32 を同じ手順で f64 のまま求め（`f64.trunc`、2^32 で割った余り。どれも丸めずに求まる）、`i64.trunc_f64_s` と `i32.wrap_i64` で i32 にする。`i32.trunc_sat_f64_s` は飽和するので使わない。`>>>` の結果は `f64.convert_i32_u` |
| `Math.floor ceil trunc abs` | プリミティブ | `f64.floor` など |
| `Math.sqrt` | `__Number_sqrt__`（負なら `NaN`） | `f64.sqrt`（負なら NaN） |
| `Math.round` | JavaScript と同じ：`r = floor(x)`、`x - r >= 0.5` なら `r + 1`、結果が 0 で `x` が負なら `-0` | 同じ手順。`f64.nearest`（偶数への丸め）は使わない |
| `Math.max`、`min` | JavaScript と同じ：NaN があれば NaN、`max(-0, 0)` は `0`、`min(-0, 0)` は `-0` | `f64.max`、`f64.min`（どちらも JavaScript と同じ） |
| `Math.sign`、単項の `-` | JavaScript と同じ（`-0` を作る） | `f64.neg` など |
| 数のリテラル | `__Number_fromString__` | 変換器が字句をそのまま WAT の `f64.const` に書き、アセンブラ（5.3）が Rust の `str::parse::<f64>` で読む（どちらも最も近い値への丸め） |

数の関数の中では、エラーは起きない（引数が数であることは呼ぶ前に確かめ、数どうしの演算はエラーにならない）。そのため、wasm 版が SJS の例外を投げる仕組みは要らない。

## 5. 仕組み

### 5.1. 変換器（consh/include/sjs_gen.se）

1. 構文木を見て、数の関数を見つける（`Gen_wasm_scan`。今の `Gen_num_names` と同じく、全体を 1 回なめる）。最初に条件を満たす関数を候補にし、数の関数でない関数を呼ぶ候補を外すことを、変わらなくなるまで繰り返す。
2. 呼び出す名前は、宣言のあと書き換えられない束縛（`function` の宣言か、関数で初期化した `const`）であること。
    * 局所の束縛なら、変換のときに決まる。
    * 大域の名前（ConSh の SJS変数）は、後の `(( ))` で書き換えられる。そこで、呼ぶ前に、大域の名前が、変換したときと同じ関数（`"id"` が同じ）を指しているかを確かめる（5.2）。
3. 数の関数をまとめて、プログラムに 1 つの wasm のモジュールの WAT（String）を作る。関数ごとに export し、数の関数どうしの呼び出しは wasm の `call` にする。
4. プログラムの始め（今の `constCode` と同じ所）に、モジュールを作る手順を置く：`Sjs_wasm_module G "<WAT>" ,(W)`。
5. 数の関数は、今の ConMa 版の Closure を、wasm 版を選ぶ Closure で包んで `Sjs_function` に渡す：`Sjs_wasm_fn W "名前" 引数の数 確かめる大域の名前 (ConMa 版) ,(f)`。
6. `--emit` の出力には WAT も入るので、変換の結果を読んで確かめられる。

### 5.2. 実行時の支え（consh/include/sjs_rt.se）

* `Sjs_wasm_module G wat ,(W)`：`__Wasm_compile__` でモジュールを作る。作れなければ（wasm のない VM、ブラウザのページの中で動いていてモジュールが大きすぎる、など）、`W` は null で、黙って ConMa 版だけを使う。
* 確かめるのは、ConMa の側から wasm 版に入るときだけで、wasm 版の中の呼び出し（再帰など）では確かめない。単独の SJS のファイルでも、ConSh のスクリプトでも、対話モードでも、同じにする（2026-11-14 に決めた）。単独のファイルなら一部を変換のときに決められるが、確かめは境界を越えるときの数回だけなので、分けない。
* `Sjs_wasm_fn` が作る Closure は、呼ばれるたびに次を確かめ、どれかが成り立たなければ ConMa 版を呼ぶ。
    * `W` が null でない。
    * 引数の数が、引数の名前の数以上（足りないと `undefined` になるので、数の関数の前提が崩れる）。余った引数は捨てる（ConMa 版と同じ）。
    * 引数がすべて Number。
    * `Math` の関数を使う関数なら、`Math` が書き換えられていない。`Math` は SJS変数の 1 つで、`Math.round = ...` で書き換えられる。実行時の支えが、`Math` のオブジェクトか名前 `Math` への書き込みで、印（PDict の `"sjs_math_changed"`）を立てる。
    * 5.1 の 2 の大域の名前が、変換したときと同じ関数を指している。
* 確かめたら、`__Wasm_call__` で wasm 版を呼ぶ（燃料とやり直しは 5.5）。
* VM が `--trace` か `CONMA_PROFILE` で動いているときは、`__Wasm_compile__` が onError を呼ぶので、wasm 版を使わない（トレースとステップ数を ConMa 版のままにする）。環境変数 `CONMA_NO_WASM=1` でも同じにする（`CONMA_NO_FOLD` と同じ形。テストで 2 つの版を比べるため）。

### 5.3. プリミティブ（高速版 ConMa、機能 `"wasm"`）

docs/BITWISE-PLAN-ja.md と同じく、高速版 ConMa（docs/FAST-PLAN-ja.md）のプリミティブとして足す。簡潔版 ConMa の言語は変えない。

**ConMa のプログラムから使える**（2026-11-14 に決めた）：SJS の中だけのものにせず、docs/PRIMITIVES.md の高速版 ConMa のプリミティブ（16 節）として書き、どの ConMa のプログラムからも使えるようにする。ConMa のプログラムに wasm の関数を書ける（インラインアセンブラの代わり）。SJS には、これを呼ぶ書き方を足さない。

* **受け付けるモジュール**（5.3.1）：import、メモリ、テーブル、大域の変数、start 関数を持たないモジュールだけを受け付ける。引数と戻り値は f64 だけで、戻り値はちょうど 1 つ。そのため、export された関数は、どれも、引数だけで戻り値が決まる関数（状態がない）になる。手で書いた WAT でも、2 の「やり直せる」が成り立ち、5.5 の燃料とやり直しを使える。
* **燃料はアセンブラが入れる**：関数の入口と、各 `loop` の始めで燃料を減らすコードを、アセンブラが入れる（5.5）。手で書いた WAT にも入るので、終わらないループを書いても VM は止まらない。燃料の大域の変数は、アセンブラが足すもので、WAT には書けない。

* `__Wasm_compile__ onError wat ,(module)`：WAT の String からモジュールを作る。WAT は、5.3.1 の部分集合だけを受け付ける。
* `__Wasm_call__ onError module name args fuel ,(status value)`：export された関数 `name` を、`args`（Number の LList。数は関数の引数の数と同じ）で呼ぶ。`fuel` は燃料（Number）。`status` は `"ok"`（`value` が戻り値）、`"fuel"`（燃料が切れた）、`"trap"`（スタックがあふれたなど。`value` は null）。
* **値**（2026-11-14 に、足すと決めた）：`Value` に `Wasm(Rc<WasmObj>)` を足す（`__type_name__` は `"Wasm"`）。`WasmObj` は、ホストのモジュールの番号を持ち、最後の参照がなくなったとき（`Drop`）にホストに消させる（`host_wasm_free`）。GC（vm/src/gc.rs）では、ほかの値を参照しない葉の値として扱う。
* **VM ごとの動き**
    * wasm 版の VM（consh/js/wasm）：5.4 のホストに渡す。
    * ネイティブの VM と変換版の VM：`__Wasm_compile__` は、アセンブラで WAT を確かめたあと、`"__Wasm_compile__: WebAssembly is not available"` で onError を呼ぶ（`__JS_call__` と同じ形）。
    * Python の VM：bin/concise で簡潔版に直したモジュールを動かす。include/ref/wasm.se に、2 つを同じ名前の関数（どちらも onError を呼ぶ）として書く。
* `(Uses "wasm")`：フロントエンドが、2 つを定義のない大域の名前として使うモジュールに付ける（FAST-PLAN-ja.md の 3.4）。

#### 5.3.1. アセンブラ

WAT をバイナリにするアセンブラを、Rust で vm/src に書く（wasm 版の VM とネイティブの VM で同じコードを使う）。一般の WAT は読まず、次の部分集合だけを受け付ける。手で書く WAT も同じである。

* `(module (func $名前 (export "名前") (param f64 ...) (result f64) (local f64 i32 i64 ...) 命令...) ...)` だけ。`import`、`memory`、`table`、`global`、`start`、`data`、`elem` は書けない。燃料の大域の変数は、アセンブラが足す（5.5）。
* 命令：`local.get`、`local.set`、`local.tee`、`f64.const`、`i32.const`、`i64.const`、f64 の算術と比較、`f64.floor` など、i32 と i64 の変換と整数の演算（ビット演算の分）、`select`、`block`、`loop`、`br`、`br_if`、`if`/`else`、`call`、`return`、`unreachable`。
* 知らない形は onError にする。ブラウザに渡す前に止めるので、エラーのメッセージがどの VM でも同じになる。

変換器がバイナリを直接出す案は採らない。ConMa の String はテキストで、バイト列を作りにくい。また、`--emit` で読めるテキストのほうが確かめやすい。

### 5.4. ホスト（consh/js/conma.js、vm-node.js、vm-jsc.js）

consh/js/wasm/src/sys.rs に import を 3 つ足す。

* `host_wasm_compile(ptr, len) -> id`：バイナリから、同期の `new WebAssembly.Module` と `new WebAssembly.Instance` でインスタンスを作る（import はない）。失敗したら負の数。
    * ブラウザでページの中で動いているとき（Worker を使えないとき）、Chrome はメインスレッドで 4 KB より大きいモジュールを同期で作らせない。そのときは失敗とし、ConMa 版で動く。
    * Content-Security-Policy は、今も `'wasm-unsafe-eval'` を許している（SAFEJS-PLAN-ja.md の 5）ので、そのままで作れる。
* `host_wasm_call(id, name_ptr, name_len, args_ptr, n, fuel, out_ptr) -> status`：燃料を大域の変数に入れて呼び、戻り値を `out_ptr` に f64 で書く。例外（trap、`RangeError` のスタックあふれ）は捕まえ、燃料の大域の変数を見て、燃料切れか trap かを返す。
* `host_wasm_free(id)`。

### 5.5. 燃料、スタック、Ctrl-C

wasm の呼び出しは同期なので、終わるまで VM のスケジューラも、ホストのイベント（Ctrl-C、端末の入力）も止まる。ConMa の VProc のように途中で止めて後で続けることは、wasm ではできない（stack switching が要る）。そこで、2 の「やり直せる」を使う（2026-11-14 に、この方式にすると決めた）。

* **燃料**：アセンブラが、関数の入口と各 `loop` の始めに、大域の変数（燃料）を 1 減らし、0 になったら `unreachable` にするコードを入れる（変換器は燃料のコードを出さない。手で書いた WAT にも入る）。
* **やり直し**：`Sjs_wasm_fn` は、燃料 F（最初は、ConMa 版の 1 回の時間の区切りに当たる量）で呼び、`"fuel"` なら、燃料を 2 倍にして始めから呼び直す。やり直しを含めた仕事の量は、最後の 1 回の 2 倍を超えない。
* **区切り**：`__Wasm_call__` は、`"fuel"` を返すとき、今の時間の区切りを終える（`conma_run` がホストに戻る）。そのため、やり直しの合間に、ほかの VProc が動き、Ctrl-C が届く。Ctrl-C が届くまでの遅れは、最後の 1 回の時間までになる。VM にこの「区切りを終える」仕組みがあるかは、作るときに確かめる（入力を待つときの仕組みが使えるか）。
* **上限**：燃料が上限（2^30 くらい）に達したら、wasm 版をやめて ConMa 版を動かす。ConMa 版は遅いが、VProc の区切りで止まるので、Ctrl-C がすぐ効く。
* **スタック**：深い再帰で wasm のスタックがあふれたら（`"trap"`）、ConMa 版を始めから動かす。ConMa 版は CChain を伸ばすだけなので、深い再帰も動く。
* ブラウザでは、Worker とページで共有する SharedArrayBuffer の印を、ループごとに見て止める方法もある。Ctrl-C はすぐ効くが、Node.js と jsc では使えない（Ctrl-C は同じスレッドのイベントで届く）。まずは燃料だけで作り、要れば足す。

### 5.6. ConSh の `(( ))`

* `(( ))` の式ごとに作るモジュール（`Sjsb_module`。同じ式は覚えておく）に、wasm のモジュールを作る手順も入る。wasm のモジュールも、ConMa のモジュールと一緒に覚えておくことになる。
* `(( ))` で定義した関数は SJS変数に入り、後の `(( ))` から呼べる。その Closure が `W` を持つので、wasm のモジュールも一緒に残る。
* 大域の名前の書き換え（5.1 の 2）は、後の `(( ))` で起きる。呼ぶ前の確かめ（5.2）で、ConMa 版に替わる。

## 6. 安全性

* wasm のモジュールには、import を 1 つも渡さない（メモリも渡さない）。数の関数は、f64 を受け取って f64 を返すことしかできず、ページ、ファイル、ネットワーク、VM のメモリに触れない。
* SJS では、モジュールは変換器が作る（`__Wasm_compile__` を SJS から呼ぶ書き方はない）。ConMa のプログラムは WAT を書けるが、アセンブラは決まった形しか受け付けない（5.3.1）：import、メモリ、テーブル、大域の変数がないので、手で書いた WAT も、数を受け取って数を返すことしかできない。燃料はアセンブラが入れる。
* 終わらないループは、燃料で区切られ、Ctrl-C で止まる（5.5）。スタックのあふれは trap になり、ConMa 版で続ける。
* そのため、`CONSH_ENABLE_JS` によらず使える。段階 B の安全性（SAFEJS-PLAN-ja.md の 5）は変わらない。

## 9. 数の関数の後で作るもの：数の配列

nbody のような計算は、配列を使うので、3 の数の関数では速くならない。配列も対象にする（2026-11-14 に決めた）。段階 5 の後に、別の計画として書く。配列を入れるには、次のどれかが要る。どれを採るかは、段階 5 で測ってから決める。

* **呼ぶときに写す**：配列（`"items"` の Dict）を wasm の線形メモリに写して呼び、戻ったら書き戻す。nbody の `advance` は、`bodies` と `pairs` の中に同じ配列が何度も出てくる（`pairs` の要素は `bodies` の要素そのもの）ので、同じ配列は 1 回だけ写し、別名を保たなければならない。呼ぶたびに全部を写すので、小さな関数では損になる。
* **数の配列という表し方を足す**：SJS の実行時の支えに、要素がすべて数の配列を、VM の中の f64 の列（新しい値）で持つ表し方を足し、wasm と共有する。ConMa 版も、それを読み書きできなければならない。中身を、数の配列だけを置く `WebAssembly.Memory` に置けば、wasm のモジュールに渡しても VM のほかのメモリには触れない（6 の安全性を保てる）。今の ConMa には配列がない（SJS の配列は Dict）ので、高速版 ConMa に新しい値を足すことになる。
* **配列のメソッドを使わないループだけ**：`for` の中で添字で読み書きするだけの配列に限る、など、範囲を狭める。

## 11. `-0` を JavaScript に合わせる

2026-11-14 に、SJS の `-0` を JavaScript に合わせると決め、同じ日に作った。wasm 版は、合わせた後の ConMa 版と同じ結果にする。

**今の違い**：ConMa の Number は IEEE 754 の倍精度なので `-0` を持てるが、プリミティブでは見えない（`__Number_is_negative__` は `x < 0`、`__Number_toString__` は整数を符号なしで書き、`__Number_divide__` は 0 で割るとエラー）。そのため、SJS は `-0` を作らず、見分けもしない。

**`-0` が見える所**：SJS では、`console.log`、`String`、テンプレート文字列、`JSON.stringify` は、どれも `-0` を `0` と書く（JavaScript の `String(-0)` と同じ。今のままでよい）。`===` も `0 === -0` は真で、`Object.is` はない。`-0` が見えるのは、0 で割ったときの無限大の符号だけである。そのため、合わせるのは次の 2 つになる。

1. **`-0` を作る**：JavaScript が `-0` を返す所で、`-0` を返す。単項の `-`（`Sjs_neg`。今は `0 - v` なので `-0` にならない。`-1` を掛ければ `-0` になる）、`Math.trunc`、`ceil`、`round`（`-0.5` から `-0` の間で `-0`）、`%`（結果が 0 なら割られる数の符号）、`Math.min(-0, 0)`、`Math.max(-0, -0)`。逆に、`Math.abs(-0)` は `0`。どれも、今のプリミティブ（`-1` を掛ける、0 どうしの和など）で求められ、新しいプリミティブは要らない。
2. **0 で割ったときに、割る数の符号を見る**：`Sjs_div` だけは、割る数が `+0` か `-0` かを知る必要があり、今のプリミティブではできない。そこで、0 の符号を調べるプリミティブを足す。

**ついでに合わせるもの**：`Math.round(0.49999999999999994)` は、今の `floor(x + 0.5)` では `1`（JavaScript は `0`）。`5 % Infinity` は、今の式では `NaN`（JavaScript は `5`）。同じ関数を直すので、一緒に合わせる。

**プリミティブ**：`__Number_is_negative_zero__ Number ,(Boolean)`（`-0` なら真。NaN を含め、ほかは偽）。結果がどの VM でもちょうど決まり、NaN の符号のビット（VM ごとに違いうる）に触れない形にした。

**簡潔版 ConMa にも足す**（2026-11-14 に決めた）：簡潔版 ConMa では、このプリミティブの代わりの定義を書けない（ConMa のプログラムからは `-0` が見えないので）。ビット演算（docs/BITWISE-PLAN-ja.md）は、高速版のプリミティブに、簡潔版の代わりの定義（include/ref/bitwise32.se）を付けたが、同じ形にはできない。そこで、高速版だけでなく、簡潔版 ConMa のプリミティブ（docs/PRIMITIVES.md、Python の VM を含むすべての VM）として足した。

**作った**（2026-11-14）：docs/ROADMAP.md の Step 42（プリミティブと test/step42）と、consh/sjs/README-ja.md の経緯の「-0」（SJS の変更と consh/sjs/test/step8 の case10）。

* **単独の SJS の Ctrl-C**：Node.js のホストは、`__OS_trap_interrupt__` を使うまで SIGINT でそのまま終わるので、単独の SJS のプログラムは、wasm 版の中でも Ctrl-C で止まる。区切りが効くのは、ConSh のように SIGINT を受け取るプログラム（段階 4）である。

## 15. 段階 4 の結果（2026-11-14）

* **(( )) の数の関数**：`(( ))` と `$(( ))` は文でなく式なので、function 宣言は書けない。そこで、式の一番外の（コンマ演算子で並べたものも）「名前 = 関数式」（function 式かアロー関数）を候補にする（sjs_wasm.se の `Wasm_prepare_expr`）。名前はその式で 1 回だけ代入され、名前の付いた function 式は、その名前が代入する名前と同じものだけ。アロー関数の本体が式なら、それを返す関数にする。1 つの `(( ))` の中の数の関数どうしは、WebAssembly の中で呼ぶ。別の `(( ))` で作った関数を呼ぶ関数は、数の関数にしない。
* **呼ぶときの確かめ**（5.2）：名前は SJS変数で、後の `(( ))` が書き換えられ、`Math` のメンバーも書き換えられる（`Math` 自体と NaN、Infinity は組み込みで書き換えられない）。そこで、`Sjs_translate_module` がモジュールの始めで `Wids`（数の関数の名前 → 作った関数の番号）を作り、関数を作るたびに番号を入れる。`Sjs_wasm_fn_checked` は、呼ぶたびに、その関数が（たどって）呼ぶ数の関数の名前の SJS変数が、どれも同じ番号の関数を指しているかと、`Math` を使うなら、`Math` のメンバー（floor、ceil、trunc、abs、sqrt、round、sign、max、min、PI）が、組み込みを作ったときの写し（G の `" math"`）と同じかを確かめ、違えば ConMa 版で動かす。ConMa 版は、JavaScript と同じく、書き換えた後の関数を呼ぶ（`oldFib = fib` の後で `fib` を書き換えると、`oldFib(20)` は新しい `fib` を呼ぶ）。
* **実行時の支え**：`Sjs_wasm_module` と `Sjs_wasm_fn_checked` を、`(( ))` のモジュールが受け取る関数（`Sjs_rt_names`、`Sjs_rt_dict`）に足した。`Sjs_wasm_fn` と `Sjs_wasm_fn_checked` は、確かめる thunk を受け取る `Sjs_wasm_fn_core` を共有する。
* **確かめたこと**：
    * consh/test/step21 の case9（fib、ループ、Math.sqrt、2 つの関数が互いに呼ぶもの、数でない引数と足りない引数、`+$n`、Math のメンバーの書き換え、名前の書き換えと古い関数）が、Rust 版の VM（ConMa 版）と wasm 版の VM（wasm 版）で同じログになる。fib(25) とループ 100 万回を含むスクリプトは、Rust 版の VM で 12.3 秒、wasm 版の VM で 2.6 秒だった。
    * ブラウザ（serve.py の Worker 版と、ヘッダーのないサーバーでページの中で動く版）で、`(( fib = ... ))` の後の `fib(27)` が 1 秒以内に出た（ConMa 版なら 5 秒ほど）。終わらない数の関数を「中断」で止められた（燃料を使い切るたびに時間の区切りが終わるので、Worker が中断を受け取る）。このモジュールは 4 KB より小さいので、ページの中でも同期で作れた。大きなモジュールがページの中で作れないときは、ConMa 版で動く。
    * jsc のホストでは、もともと `(( ))` のモジュールを作れない（段階 A だけ。consh/js/README-ja.md）ので、段階 4 の対象にならない。
* **前からのこと**：対話モードで、コマンド行が `(( 名前 = 関数式 ))` で始まると、値を出そうとして「関数の値は文字列にできない」と出る（変更の前の main でも同じ）。代入はされる。

## 16. 段階 5 の結果（2026-11-14）

`consh/sjs/bench/run.sh` に、wasm 版の VM の 3 つの列（数の関数を wasm 版で、`CONMA_NO_WASM=1` で ConMa 版だけで、手で書いた ConMa）を足して測った（fe4d82e、Apple M1、user + sys 秒の 3 回の最良。表は consh/sjs/README-ja.md の「速さ」）。

* **loop と fib**：関数が 1 つずつ数の関数になり（WAT は 1,700 バイト）、wasm 版の VM での時間は、ほとんどが起動（約 0.13 秒）になった。loop 10000000 は ConMa 版だけの 22.14 秒が 0.172 秒（1/129）、fib 27 は 4.729 秒が 0.149 秒（1/32）。Rust 版の VM の SJS（15.77 秒、3.511 秒）と、手で書いた ConMa（2.738 秒、0.258 秒）より速い。CPython（0.347 秒、0.040 秒）とは、loop 10000000 では速く、fib 27 では起動の分だけ遅い。小さい N（loop 100000、fib 20）では、起動の分だけ、Rust 版の VM の SJS と同じくらいになる。
* **nbody**：配列を使うので数の関数がなく、変わらない（1.66 秒）。9 の配列を作らないと、速くならない。
* **変換**：数の関数を探すようになって、変換の時間は 0.006〜0.007 秒増えた（nbody 0.216 秒 → 0.223 秒）。consh/include/sjs_wasm.se は 1,125 行。
* **wasm 版の VM と Rust 版の VM**：数の関数がないとき、wasm 版の VM の ConMa 版は、Rust 版の VM の 1.4〜1.5 倍の時間（loop 10000000 が 15.77 秒と 22.14 秒、nbody 2000 が 1.08 秒と 1.665 秒）。
