# JavaScript 版 ConSh の仕様と設計のレビュー

[PLAN-ja.md](PLAN-ja.md)、[README-ja.md](README-ja.md)、`conma.js`（`evaluateStatement`、`keep`）、`consh/include/consh_jsstmt.se` を読んで行った（main の 34b8e84、2026-11-09）。動かして確かめたものではない。重い順に並べる。

## 1. 設計上のリスク（直したほうがよいもの）

### 1.1 知らない名前への代入が、グローバル変数に入ることがある

`conma.js` の Proxy の `has` は、`globalThis` にあってシェルの変数でない名前に `false` を返す。そのため、ブラウザで `name = "x"` と書くと `window.name` に入り、シェルの変数はできない。`status`、`length`、`event`、`print` なども同じで、`top = 3` はエラーも出ずに何も起きないはずである。Node.js では `process = 1` などがそうなる。「代入はシェルの変数になる」という仕様に反するが、PLAN にも README にも書かれていない。

案：代入先は `globalThis` にあってもシェルの変数にする（`set` で受ける）か、グローバルへの代入は `globalThis.x = ...` と明示する形だけにする。

### 1.2 await をはさむと、JS の値の変数の更新が失われる

文が終わると `flush` が、渡した JS の値の変数（`ids` にあるもの全部）を、書いていなくても `(w ...)` で書き戻す。`await` の間にほかの VProc（`&` のジョブなど）がその変数に代入すると、文の始めの値で上書きされる。

案：書いていない変数は、オブジェクトの変化をシェルの値に直すだけにして番号を戻さない。または、番号が変わっていなければ書き戻さない。

### 1.3 JS の値の表がふくらみ続ける

`keep` は代入のたびに表の番号を新しく取る。値が文字列や数でも同じで、解放はない。ループで `i = i + 1` と書けば 1 回ごとに 1 つ増える。PLAN の 4 は表の解放を残りとしているが、文の数に比例して増えることは書いていない。

案：文字列などのプリミティブは表に入れない（シェルの値だけで足りる）。同じ変数に代入したら前の番号を捨てる。

### 1.4 文ごとの費用が、JS の値の変数の数に比例する

`Js_stmt_jsvars` は、コードに現れなくても JS の値の変数をすべて渡し、ホストは文ごとにそれらをすべて `JSON.stringify` などでシェルの値に直す。大きなオブジェクトを 1 つ持つだけで、関係のない文もすべて重くなる。

案：シェルの値には `$o` で読むときに遅延して直す。

## 2. 仕様のあいまいさ（決めて書くべきもの）

### 2.1 打ち間違えの判定が先頭の名前だけ

先頭の名前が未定義の ReferenceError だけシェルに回し、ほかの ReferenceError はエラーにする区別は妥当である。ただし、`failed` は Fallback を返す前に `flush` する。そのため、先頭が未定義になる前に代入が起きていれば（`f(x = 1)` で f が未定義など）、代入は残ったまま、シェルの文として 2 度目の実行になる。めったにないが、仕様として書いておくべきである。

SyntaxError でシェルに回すときも、JS を書き間違えたのに「コマンドが見つからない」と出るので戸惑う。

案：`(f ...)` のメッセージを `command not found` の後に添えるか、変数（`CONSH_JS_DEBUG` など）で JS のエラーを出せるようにする。

### 2.2 JS かどうかの判定が、解析時の環境で決まる

PATH と解析時にわかる関数で決まる。そのため、同じスクリプトでも、マシン（macOS の `x`、`w`）、PATH、関数の定義の順で意味が変わる。対話モードとスクリプトでも、わかっている関数の範囲が違う。README に 1 行あるが、「移植できるスクリプトでは `js '...'` を使う」という指針があるとよい。

### 2.3 空白の有無で意味が変わる

`n=1+2` は String、`n = 1+2` は数 3 になる。意図された仕様だが、シェルに慣れた人ほど引っかかるので、README の例の近くに対照として明示するとよい。

### 2.4 文の始めの if、for、function

書かれてはいるが、JS の `if (x) ...` はシェルの `if` として解析エラーになるはずで、そのメッセージを決めておくとよい。PLAN にある `if 文; then` で JS の条件が `; then` を飲み込む件は、README にない。

### 2.5 console の出力の帰属

`js` の呼び出しが並行して走るとき、`console.log` がどの呼び出しの標準出力に出るか（最後に始まった呼び出しか、非同期の継続でも元の呼び出しか）が仕様にないように見える。明記すべきである。

### 2.6 遅延の LazyList の後始末

終わらないジェネレータを変数に入れて途中まで読むと、ホストのイテレータと Job が残り続ける。`return()` を呼ぶ時（変数が捨てられたとき、シェルが終わるとき）が決まっていない。

## 3. ドキュメントの古い記述と食い違い

* README の「作る」はモジュールを約 5.8 MB、PLAN の 2.2.5 は約 5 MB で bin/includer で作るとしている。今は約 2.2 MB で、conma build で作る。
* PLAN の 2.1.3（段階 5 から `new Function`）と 2.2.4 で、評価のしかたの説明が 2 通りある。今の実装は、式、async の式、async 関数の本体の 3 段である。
* 2.5.4 の `js 変数名=` に JS の値を入れる件は、3.15 と README には未実装とあるが、2.5.4 の本文にも明記したほうが読み違えない。

## 4. テストと移植性

* JS の文の構文解析は ConMa 版の parser（速い版と参照版）にだけあり、Python 版と Rust 版の ConSh にはない。`x = 1` の行は、Rust 版（製品）ではコマンドが見つからず、JS 版では代入になる。Rust 版には入れない、ずっと JS 版だけ、といった方針を PLAN の 1 に書いておくとよい。
* エラーメッセージは JS エンジン（V8、JavaScriptCore、SpiderMonkey）で違う。テストが文言に頼れば、ブラウザごとに結果が変わる。
* ブラウザの `serverfs.js` は同期の XHR でメインスレッドを止めるので、大きなファイルや遅いサーバーで UI が固まる。Worker に移す案を残りの課題に挙げておく価値がある。

## 5. よいところ

* `js` を組み込みコマンドとし、`__JS_call__` という 1 つのプリミティブと行の S 式のプロトコルにまとめていて、VM の変更が小さい。
* イテレータを遅延の LazyList にし、終わらないジェネレータもパイプで使えるのは、シェルの性質とよく合う。
* 打ち間違えたコマンドが今までどおり 127 になるようにフォールバックを入れたのは、互換性への配慮としてよい。
* 判定のための関数の走査（`Funcs_scan`）は、テキスト全体の `function name` まで見ており、後で定義される関数にも対応している。

### 6.3 気になった点

1. **分割代入では、今も大域変数に入る。**
   * 代入される名前を探す `rewriteDeclarations` は、`x =`、`x +=`、`x++`、`++x` の形しか見ない。
   * Node.js で `[performance] = [2]` とすると、シェルの変数はできず、`globalThis.performance` が数の 2 になる（実行して確かめた）。
   * ブラウザで `[name] = ["x"]` とすれば、`window.name` が変わるはずである。`({ navigator } = {...})` も同じである。
   * 案：分割代入のパターンの中の名前も、代入される名前に数える。または、`set` で受けた名前を後から確かめる。
2. **括弧で囲んだ分割代入は値を出す。** `({ status } = {status: 3})` は `{"status":3}` を出し、「代入は何も出さない」に合わない。代入かどうかを深さ 0 の `=` だけで判定しているためで、害は小さい。
3. **Worker で動かすときの `$x` の費用。** オブジェクトの変数の `$x` は、読むたびに `Atomics.wait` でページに尋ねる。ループの中で何度も読むと遅くなりそうである（測っていない）。
4. **JS の値は、作った呼び出しの単位で消える。** 1 つの文で `a = {}; big = [...]` とすると、`big` を代入し直しても、`a` が残る間は `big` の前の値も表に残る。設計どおりで、PLAN の 3.18 からも読み取れるが、明記してもよい。
5. **COEP の影響。** serve.py が `Cross-Origin-Embedder-Policy: require-corp` を送るので、ページから別のオリジンの画像やスクリプトを no-cors で読むと止められる。CORS の `fetch` は動く。README に一言あるとよい。
